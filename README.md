# 자취선배 팀 빌딩 랜딩 — A안

지원금과 후보 집의 조건을 함께 확인해 계약 전 판단을 돕는 **첫 자취 생활
내비게이터**의 팀 빌딩 비교용 랜딩페이지입니다.

> 이 작업은 `codex/team-building-support-reframe` 브랜치와 Vercel Preview에서만 진행합니다.
> 기존 자루 랜딩은 `main` 브랜치와 `https://zaru-landing.vercel.app/`에 그대로 보존합니다.
> 기준 팀 빌딩 랜딩 `codex/team-building-landing`과 기존 Preview도 변경하지 않습니다.

## 목적

- 초기 응답 10건에서 반복된 지원금과 집 선택 문제를 크루에게 공유
- 나와 후보 집의 조건을 함께 확인하는 계약 전 흐름을 설명
- 지원금 목록 열람이 아니라 질문·비교·계약 판단 변화로 가치를 검증
- 확정 판정 없이 공식 기관 최종 확인이 필요하다는 경계를 명확히 안내

## 서비스 정의

> 이 집을 계약하면 어떤 지원을 알아볼 수 있고, 어떤 지원을 놓치게 될까?

```
나의 조건 → 후보 집 조건 → 지원 가능성 안내 → 질문·증빙 준비 → 공식 기관
```

초기 범위는 지원금 가능성 확인, 집 보러 가기, 입주 준비입니다. 첫 번째 핵심
검증은 지원금과 후보 집 조건을 계약 전에 함께 확인했을 때 실제 판단이 달라지는지입니다.

## 페이지 구성

1. 헤더
2. 히어로
3. 초기 사용자 응답
4. 계약 전에 함께 확인해야 하는 조건
5. 자취선배의 첫 번째 흐름
6. 지원금과 집 보러 가기의 연결
7. 계약 전 기록이 신청과 입주 준비로 이어지는 구조
8. 전체 자취 타임라인
9. 검증 계획
10. 팀 빌딩 CTA
11. 푸터

## 기술 스택

- Vite + React 18 + TypeScript
- 순수 CSS — 새 UI 라이브러리 없음
- IntersectionObserver 기반 reveal과 스크롤 진행률
- `prefers-reduced-motion` 대응
- Supabase 이벤트 계측 · Vercel 배포

## 실행과 검증

```bash
npm install
npm run dev
npm run typecheck
npm run build
npm run preview
```

확인 항목:

- 데스크톱·모바일 레이아웃
- 스크롤 reveal, 상단 진행 바, 헤더 compact 전환
- reduced motion에서 모든 콘텐츠가 즉시 노출되는지
- 콘솔 오류가 없는지

## 계측

| 이벤트 | 시점 |
|---|---|
| `view` | 페이지 진입 |
| `depth` | 스크롤 25/50/75/100% |
| `step_view` | 세 가지 순간 도달 |

사전예약 이메일 폼과 `notify`, `kakao_click` 이벤트는 현재 방향에서 제거했습니다.

## 이전 방향: 자루 루틴 서비스

이 저장소의 `main`은 자취 청소·관리 주기를 잡아주고 알림으로 재방문을 유도하던 **자루 루틴 서비스 사전예약 랜딩**입니다. 실제 앱 캡처, 이메일 사전예약, 카카오톡 알림 CTA를 사용했습니다.

이전 방향은 삭제하거나 운영 페이지에서 교체하지 않습니다. 구체적인 검증 결과와 피벗 배경은 `docs/CONTEXT.md`에 남겨두었습니다.
